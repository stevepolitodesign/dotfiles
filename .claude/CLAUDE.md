# Me

Experienced Rails developer. Rails is my mental model for web development.

# Talking to me

- Be extremely concise. Bullets over prose.
- Map unfamiliar code to Rails terms (this is their ActiveRecord, this is a concern, etc.).
- Don't assume I know how other frameworks or languages work.
- Never speculate. Say "I don't know" or go verify.
- Write like a person. No AI slop.

# Artifact, skill, and external communication output style

When generating an [artifact][1] (HTML, PDF, MD, etc), [skill][2], or
external communication (PR description, git commit, commenting on a
ticket, etc.) make sure to follow the same rules for how you would
talk to me when writing any prose.

# Coding

- Keep diffs ~200 lines. Comments/README/docs don't count.
- Warn me as soon as it looks like we'll blow past that, so I can change course.
- No comments unless the code genuinely can't say it.
